function calculateModbusCRC(data) {

var crc = 0xFFFF;

for (var i = 0; i < data.length; i++) {

crc ^= data[i];

for (var j = 0; j < 8; j++) {

if ((crc & 0x0001) !== 0) {

crc >>= 1;

crc ^= 0xA001;

} else {

crc >>= 1;

}

}

}

return crc;

}

function LEdecToHexBytes(dec) {

var highByte = (dec >> 8) & 0xFF;

var lowByte = dec & 0xFF;

return [lowByte, highByte];

}

function BEdecToHexBytes(dec) {

var highByte = (dec >> 8) & 0xFF;

var lowByte = dec & 0xFF;

return [highByte, lowByte];

}

return encoded;

}

In the code above, the blue text represents the data processing section for Channel 1, and the red text represents the data processing section for Channel 2. The remaining black text code should not undergo any modifications.

Regarding the code in blue text for the Channel 1:

According to the Modbus RTU standard protocol, a complete Modbus RTU command consists of the Slave ID, Function Code, Register Address, Number of Registers, and CRC checksum. In the figure below, the first red box represents the Modbus RTU command used to read Modbus Channel 1, while the second red box represents an incomplete command used for writing to Modbus Channel 1. Since Modbus Channel 1 of the UC100 is connected to holding registers, I should use 0x03 as the function code for read operations (0x03 stands for "Read Holding Registers"), and use 0x06 as the function code for write operations (0x06 stands for "Write Single Holding Register").

Because Channel 1 corresponds to a slave ID of 1, converting it to a 2-digit hexadecimal number gives us 0x01. The starting address for Channel 1 is 0, which converts to a 4-digit hexadecimal number of 0x0000. The register count for Channel 1 is 1, which converts to a 4-digit hexadecimal number of 0x0001. We need to append 0x03 after the hexadecimal representation of the slave ID, and then concatenate these hexadecimal numbers together. This gives us the sequence: 010300000001. When we perform CRC-16 (Modbus) checksum validation on this sequence using a computer browser, we obtain a 4-digit hexadecimal data of 0x840A. Therefore, our final sequence of hexadecimal numbers is: 010300000001840A. We will place this sequence after the "return" statement in the code, grouping them every two digits.
