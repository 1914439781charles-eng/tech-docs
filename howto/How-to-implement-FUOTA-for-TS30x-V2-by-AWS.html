How to implement FUOTA for TS30x V2 by AWS

Overview

This document describes how to perform bulk remote firmware update (FUOTA) for TS30x V2 devices on AWS IoT Core for LoRaWAN.

Update Method

AWS IoT Core delivers firmware to multiple devices simultaneously via multicast using the FUOTA task mechanism. Devices will receive, verify and install the firmware automatically.

Pre-Upgrade Checks

You have logged in to your AWS account.

Devices have been created and properly configured.

The associated gateways are online.

Target devices support the FUOTA function and are correctly configured.

Step 1: Check Device Configuration

Ensure the working mode of the target devices' **Device Profile** is set to **Class A**, and FUOTA support is enabled in device configuration. The FUOTA option must be enabled when adding devices on the AWS platform to successfully deliver and apply firmware updates via FUOTA multicast.

Operation Path:

Log in to the AWS IoT Console → Click **IoT Core** → Select **LPWAN** from the left menu → Go to **Devices** → Locate the target device → Click **Profiles** of the device and copy the ID → Verify the device profile is set to **Class A**.

2. Operating Steps:

- Navigate to the **Multicast groups** page and create a multicast group.

- Customize the multicast group name.

- Add devices: Select the device frequency band, set the operating mode of multicast devices to **Class C**. Add devices one by one by ID, or select devices via device profile (the dedicated profile is exclusively for TS30X devices).

- Verify the creation status of the multicast group.

- Wait until all devices in the multicast group show Multicast setup ready. The status updates upon the device's next data uplink, so the waiting time depends on the sensor's reporting interval. A green icon indicates ready status, while a grey icon means not ready. See two solutions below for devices with the grey status.

Solution ①: After creating the multicast group, wait for one sensor reporting cycle. If a device remains in **Package attempting** status after this period, remove it from the multicast group, then re-add it. Wait for another reporting cycle and check if its status changes to **Multicast setup ready**. As shown below.

Solution ②: If some devices stay in **Package attempting** status after one reporting cycle following multicast group creation, remove these unready devices (be sure to record their IDs). Prioritize running FUOTA tasks for devices marked **Multicast setup ready**. For the remaining unready devices, create a new multicast group and wait again. This method can greatly reduce waiting time.

2. Startup Operations:

On the FUOTA task details page, click **Schedule FUOTA task** and set the start time. It is recommended to schedule the task to start after **6 times the device reporting cycle** to reserve time for session retries. For example, if the reporting cycle of TS30x V2 is 10 minutes and all devices in the multicast group are in **Multicast setup ready** status, set the FUOTA task to start in 60 minutes.

Partial Device Failures:

Devices remaining in the initial state after task completion indicate upgrade failures.

Troubleshooting Steps for Failures:

① Since the platform does not support upgrade retries, record the IDs of failed devices.

② Delete the original multicast group and FUOTA task from the platform, as shown below.

③ Go back to Step 3: Create a multicast group and restart the operation.

Important Reminders:

Key Points Description
Test with a small batch first Select 2-3 devices for a trial run on the first upgrade. Carry out bulk execution after confirming the process runs normally.
No device operation during upgrade Do not power off devices or modify configurations while upgrading.
Delete and recreate for retry AWS FUOTA does not support retry. Delete and recreate the multicast group and FUOTA task after upgrade failures.
